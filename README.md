# Video Unique Service

Локальный MVP на Java 25, Spring Boot 4, Maven и FFmpeg. Загружает видео, меняет скорость и масштаб, отдаёт MP4 (H.264, yuv420p, AAC при наличии аудио) с SHA-256 исходного и итогового файлов.

**Разные SHA-256 означают только побайтовое различие. Сервис не гарантирует уникальность для алгоритмов социальных платформ и не обещает обход распознавания дубликатов.**

## Установка и запуск

Нужны стабильный JDK 25, Maven 3.6.3+ и FFmpeg/ffprobe с кодировщиками libx264 и AAC. Проверьте `java -version`, `mvn -version`, `ffmpeg -version`, `ffprobe -version`.

- Windows: скачайте сборку по ссылкам на https://ffmpeg.org/download.html, распакуйте и добавьте каталог `bin` в PATH.
- macOS: `brew install ffmpeg`.
- Ubuntu/Debian: `sudo apt update && sudo apt install ffmpeg`.

Установите `JAVA_HOME` на JDK 25. Если FFmpeg не в PATH, задайте `FFMPEG_PATH` и `FFPROBE_PATH` (полные пути к исполняемым файлам).

```sh
mvn clean verify
mvn spring-boot:run
# либо после mvn package:
java -jar target/video-unique-service-0.1.0-SNAPSHOT.jar
```

API: http://localhost:8080/api/videos/unique

Swagger UI: http://localhost:8080/swagger-ui/index.html

OpenAPI JSON: http://localhost:8080/v3/api-docs

Сервис по умолчанию слушает только 127.0.0.1. Для другого интерфейса задайте `SERVER_ADDRESS`. Аутентификация и публичный хостинг в MVP не входят.

## Запрос

```sh
curl --fail-with-body -X POST http://localhost:8080/api/videos/unique \
  -F 'file=@input.mp4' -F 'speed=1.01' -F 'scale=0.98' \
  -D headers.txt -o unique.mp4
```

PowerShell (используйте именно `curl.exe`):

```powershell
curl.exe --fail-with-body http://localhost:8080/api/videos/unique -F "file=@C:\videos\input.mp4" -F "speed=1.01" -F "scale=0.98" -D headers.txt -o unique.mp4
```

Параметры можно не передавать: `speed=1.01`, `scale=0.98`. Допустимы конечные числа: speed от 0.5 до 2.0, scale от 0.5 до 1.0. Scale уменьшает изображение и добавляет чёрные поля по центру; размеры округляются для H.264 до чётных чисел, поэтому возможна разница в несколько пикселей. Нет обещания, что поля будут скрыты социальной платформой.

Принимаются `.mp4` и, для совместимости с iPhone-примерами, `.mov`. Расширения недостаточно: ffprobe проверяет контейнер семейства MP4/MOV и наличие видео. MIME клиента не считается доказательством формата. Обрабатываются первые видео- и аудиодорожки; субтитры, главы и метаданные не переносятся. Для видео без звука аудиодорожка не создаётся. Скорость звука меняется через atempo с сохранением высоты тона. HDR/цветокоррекция и точное сохранение несquare pixel aspect ratio в MVP не входят.

Ответ: `Content-Type: video/mp4`, `Content-Disposition: attachment; filename=unique.mp4`, `X-Hash-Before` и `X-Hash-After` — полные 64-символьные SHA-256. Ошибки возвращаются как Problem Detail JSON. При ошибке curl может записать JSON вместо видео — проверяйте код возврата и HTTP-статус.

| Статус | Причина |
|---|---|
| 400 | Нет файла, пустой файл, неверное расширение или параметры |
| 413 | Превышен размер загрузки |
| 422 | Повреждённый/неподдерживаемый контейнер или ошибка декодирования |
| 429 | Все слоты обработки заняты |
| 503 | FFmpeg/ffprobe недоступен или запрос прерван |
| 504 | Истёк таймаут процесса |
| 500 | Ошибка файловой системы или другая внутренняя ошибка |

## Настройки и ограничения

`application.yml`: файл до 200 MB, multipart-запрос до 201 MB, два одновременных запроса обработки, два потока кодировщика на FFmpeg. `video.timeout` (по умолчанию 2m, переменная `VIDEO_TIMEOUT`) применяется отдельно к ffprobe и FFmpeg. `VIDEO_MAX_CONCURRENT` меняет число слотов. Загрузка, вычисление хешей и отдача файла не входят в таймаут процесса. Это синхронный API: клиент должен ждать до завершения обработки.

Файлы хранятся на диске во временном каталоге Java; путь можно задать через `-Djava.io.tmpdir=...`. Каждый запрос использует отдельный каталог с префиксом `vuniq-managed-` и блокировкой, которая действует весь период обработки. После передачи результата, ошибки, таймаута или обнаруженного отключения клиента файлы удаляются в `try-with-resources`. При аварийном завершении или отключении питания немедленное удаление не гарантируется: при следующем запуске приложение удалит оставшиеся управляемые каталоги; повторная проверка выполняется каждые пять минут. Если файл пока занят или недоступен, очистка повторится позднее. Блокировка защищает активные каталоги, включая каталоги другого экземпляра. Служебный пустой файл `vuniq-workspace.guard` остаётся в системном временном каталоге. Старые каталоги `video-unique-*`, созданные предыдущими версиями, автоматически не удаляются: они не имеют признака владения, поэтому их нужно проверить и удалить вручную при остановленных приложениях. Требуется свободное место для исходных, промежуточных и выходных файлов; выходной размер отдельно не ограничен.

Эта очистка относится только к рабочим файлам сервиса. Она не удаляет сообщения и медиа в Telegram, загруженные пользователем файлы, вручную сохранённые результаты, а также временные файлы внешних компонентов. `java.io.tmpdir` должен оставаться одинаковым между запусками для обнаружения старых каталогов. REST multipart может дополнительно создавать файлы контейнера сервлетов; их жизненный цикл управляется контейнером, а не этим механизмом. Это обычное удаление файлов, а не гарантированное безвозвратное стирание носителя или резервных копий.

Процессы запускаются через ProcessBuilder без shell; доступ к протоколам ограничен локальными файлами. Вывод процесса постоянно вычитывается с ограничением удерживаемой памяти. Это не песочница для публичной обработки недоверенных видео: перед публичным размещением нужны изоляция процессов и ограничения ресурсов/доступа. При медленном клиенте слот удерживается до окончания скачивания. Очередь, БД и Docker не включены в MVP. Telegram-бот подключается опционально, см. ниже.

## Тесты

`mvn test` запускает тесты параметров, SHA-256, очистки, ограничения параллелизма, обработки ошибок процесса, контроллера, OpenAPI и Swagger. Тесты JUnit 5.14.1; его версия явно зафиксирована вместо управляемого Boot JUnit 6. Spring Framework 7 SpringExtension требует JUnit 6, поэтому API-тесты сами запускают и закрывают Spring-контекст, без SpringExtension. Интеграционные тесты FFmpeg по умолчанию пропускаются явно (два теста); для реального кодирования:

```sh
RUN_FFMPEG_TESTS=true mvn clean verify
```

```powershell
$env:RUN_FFMPEG_TESTS='true'
mvn clean verify
```

Они генерируют двухсекундные видео с аудио и без него и проверяют кодеки, длительность, разные хеши и отказ на повреждённом файле. FFmpeg и ffprobe должны быть доступны через PATH или указанные переменные окружения. Пользовательские видео и результаты не включаются в Git.

## Архитектура

- `controller`: multipart и HTTP, потоковая передача с диска без загрузки всего результата в память.
- `service`: ограничения параллелизма, временные файлы, хеши, ffprobe/FFmpeg и управление процессами.
- `config`: типизированные настройки.
- `dto`: неизменяемые параметры обработки с проверкой инвариантов.
- `exception`: единый контракт ошибок без раскрытия stderr и локальных путей.

Spring dependency injection; без Lombok и preview-функций Java. REST API работает без внешних сервисов; опциональный бот использует Telegram Bot API.

## Telegram-бот

Бот опционален и по умолчанию выключен. Использует long polling: публичный сервер, HTTPS-домен и webhook не нужны. Пока приложение работает и имеет доступ к api.telegram.org, бот отвечает в личных чатах.

1. Создайте бота командой `/newbot` у официального [@BotFather](https://t.me/BotFather).
2. Соберите приложение: `mvn verify`.
3. Windows: выполните `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/configure-telegram.ps1` и вставьте токен в скрытый запрос. Скрипт сохраняет его в `.local/telegram.properties`; весь каталог исключён из Git. Это обычный локальный файл с секретом — не публикуйте его и не добавляйте в архивы.
4. Запустите `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run-telegram.ps1`. Если порт занят, добавьте `-Port 8081`.
5. Откройте своего бота, нажмите Start, отправьте видео или документ MP4/MOV.

На Linux/macOS передайте `TELEGRAM_ENABLED=true` и `TELEGRAM_TOKEN` через окружение процесса и запустите JAR; не записывайте реальный токен в командную историю. JDK 25, FFmpeg и ffprobe нужны так же, как для REST API.

Windows-скрипт запуска включает `-Djava.net.useSystemProxies=true`, чтобы Java использовала системный прокси, если он настроен. При ручном запуске добавьте этот параметр перед `-jar`, если прямое соединение с Telegram недоступно. Токен не передаётся в командной строке.

Команды: `/start` — главное меню, `/settings` — режим и 1–10 копий, `/subscription` — статистика и макет тарифов, `/help` — инструкция, `/id` — ID личного чата. Telegram показывает эти команды в кнопке «Меню». При запуске бот обновляет список команд и описание через Bot API.

По умолчанию создаются **3 Basic-копии**. В Basic первая копия использует `speed=1.01 scale=0.98`, в Hard — `speed=1.04 scale=0.94` и более заметную коррекцию контраста/насыщенности/яркости. Каждая следующая копия имеет немного другие параметры. Подпись `speed=1.05 scale=0.95` переопределяет параметры первой копии; подпись должна содержать только параметры. Хеши копий проверяются на различие внутри задания; повторная отправка одного исходника с теми же настройками может дать те же файлы.

Фото принимаются как Telegram photo или JPEG/PNG-документы до 20 мегапикселей. Результат — JPEG-документ: масштабирование с полями и небольшое изменение тона, в Hard — усиленная коррекция. Анимация, HEIC, RAW, EXIF-ориентация и профессиональное управление цветом не поддерживаются. Видео возвращаются MP4 с плеером и ответом на исходное сообщение. Хеши в подписях относятся к файлам, загруженным ботом в Telegram; платформа может создавать свои превью/версии. Для точного исходного хеша отправляйте медиа документом.

Прогресс выводится одним редактируемым сообщением: очередь, обработка, отправка, завершение/ошибка для каждой копии. Процент видео вычисляется из временной позиции FFmpeg и длительности; для фото отображаются только этапы. Обновление — не чаще раза в 3 секунды (доставка зависит от сети), короткие видео могут сразу перейти в завершённое состояние. Сбой обновления прогресса не прерывает кодирование.

**Оплата отключена.** Кнопки Basic 990 ₽/мес и PRO 4 990 ₽/мес — явно помеченные макеты по референсу, без invoices, платёжных провайдеров и списаний. Все режимы и 1–10 копий доступны бесплатно. Демонстрационный счётчик 3 исходников не блокирует обработку. Приоритетной платной очереди нет. Настройки и статистика сохраняются в `users` рядом с offset-файлом (`.local/users` по умолчанию). Статистика сбрасывается при наступлении календарного месяца по Europe/Moscow, настройки сохраняются. Исходник учитывается при первой успешно отправленной копии, каждая отправленная копия — отдельно; неудачные отправки не учитываются. При аварийном завершении между отправкой и записью статистики возможен недоучёт.

Фон, цвет сообщений и внешний вид системной кнопки «Меню» определяются темой клиента Telegram. Бот управляет текстом, форматированием, inline-кнопками и медиа, но не темой приложения.

Стандартный облачный [Telegram Bot API](https://core.telegram.org/bots/api#getfile) разрешает боту скачать файл до 20 МБ и отправить документ до 50 МБ. В коде применены консервативные десятичные пределы 20 000 000 / 50 000 000 байт. Они не меняют лимит REST API 200 MB. Размер проверяется по метаданным и при потоковом скачивании. Выходной файл больше лимита не отправляется; пользователь получает объяснение. Локальный Bot API Server для больших файлов в эту версию не входит.

Настройки:

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `TELEGRAM_ENABLED` | `false` | Включить polling |
| `TELEGRAM_TOKEN` | пусто | Токен BotFather |
| `TELEGRAM_ALLOWED_CHAT_IDS` | пусто | Разрешённые ID через запятую; пусто — все личные чаты |
| `TELEGRAM_OFFSET_FILE` | `.local/telegram-offset.txt` | Локальное состояние polling |

Также можно добавить `telegram.allowed-chat-ids=123456789` в `.local/telegram.properties`. Узнать свой ID можно через `/id` до включения ограничения. Группы игнорируются.

Запускайте только один экземпляр polling для одного токена; webhook должен отсутствовать (для нового бота его нет). Ошибки связи и rate limit вызывают повтор polling с задержкой, учитывается `retry_after`. Токен и URL Telegram не выводятся в диагностике ошибок. Для медиа выделен один рабочий поток и очередь максимум из двух ожидающих заданий в памяти. У одного чата может быть только одно незавершённое задание. Меню работает независимо от кодирования. Слоты обработки общие с REST API внутри одного процесса.

До сохранения offset бот записывает обновление и параметры задания в локальный журнал рядом с offset-файлом (по умолчанию `.local/telegram-offset.txt.jobs`). После перезапуска незавершённые задания восстанавливаются, а уже подтверждённые копии повторно не отправляются. В журнале находятся служебные данные Telegram и настройки, но не сами медиафайлы; завершённые записи удаляются после подтверждения offset. Используйте отдельный offset-файл для каждого токена и запускайте только один экземпляр для каждого токена. Блокировка offset-файла не позволит двум локальным процессам одновременно использовать один и тот же журнал; она не обнаруживает экземпляры с другим offset-файлом.

Повреждённые записи журнала переносятся в подкаталог `quarantine` рядом с заданиями. Бот продолжает обрабатывать остальные сообщения и не выполняет автоматически повторно обновление, чьё состояние доставки неизвестно. Файлы карантина сохраняются для ручной проверки и могут содержать служебные данные пользователя. При остановке блокировка журнала удерживается до завершения polling и медиаворкера; если остановка затянулась, блокировка освобождается после фактического выхода потоков.

При ответе Telegram HTTP 429 отправка повторяется не более трёх раз с паузой не меньше `retry_after`; при исчерпании попыток бот сообщает об ошибке. Если соединение оборвалось после начала отправки или приложение завершилось во время неё, нельзя определить, дошёл ли файл: бот просит проверить чат и автоматически эту копию не отправляет. Возможен недоучёт статистики, если сбой случился между успешной отправкой и записью счётчика. Автоматическое восстановление предполагает доступность исходного файла по Telegram `file_id` и не является гарантией сохранности при отключении питания или повреждении диска.

В Windows приложение помещает JVM и создаваемые ею медиапроцессы в Job Object с `KILL_ON_JOB_CLOSE`, чтобы ОС завершала FFmpeg при аварийном завершении JVM. Если Windows не разрешает назначение Job Object, обработка не стартует. На других ОС принудительное завершение потомков при аварии JVM не гарантируется; обычная остановка и таймаут используют Java Process API. При первом запуске обрабатываются ожидающие сообщения Telegram. Остановка возможна через Ctrl+C; завершение сетевого запроса может занять до 60 секунд.

Тесты бота используют локальный HTTP-сервер вместо Telegram: проверяют polling, скачивание, multipart-отправку, rate limit, ограничения размера, подписи, хеши в ответе, фильтрацию чатов и сохранение offset. Они не требуют токена и не отправляют сообщения реальным пользователям. При `RUN_FFMPEG_TESTS=true` в Windows также выполняются тесты аварийного завершения JVM, восстановления заданий и повторной отправки через локальный имитатор Telegram. Полная проверка живого бота требует локального токена и отправки видео пользователем.
