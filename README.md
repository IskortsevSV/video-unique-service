# Video Unique Service

Локальный MVP на Java 25, Spring Boot 4, Maven и FFmpeg. Загружает видео, меняет скорость и масштаб, отдаёт MP4 (H.264, yuv420p, AAC при наличии аудио) с SHA-256 исходного и итогового файлов.

**Разные SHA-256 означают только побайтовое различие. Сервис не гарантирует уникальность для алгоритмов социальных платформ и не обещает обход распознавания дубликатов.**

## Установка и запуск

Нужны стабильный JDK 25, Maven 3.6.3+ и FFmpeg/ffprobe с кодировщиками libx264 и AAC. Проверьте `java -version`, `mvn -version`, `ffmpeg -version`, `ffprobe -version`.

- Windows: скачайте сборку по ссылкам на https://ffmpeg.org/download.html, распакуйте и добавьте каталог `bin` в PATH.
- macOS: `brew install ffmpeg`.
- Ubuntu/Debian: `sudo apt update && sudo apt install ffmpeg`.

Установите `JAVA_HOME` на JDK 25. Если FFmpeg не в PATH, задайте `FFMPEG_PATH` и `FFPROBE_PATH` (полные пути к исполняемым файлам).

```sh
mvn clean verify
mvn spring-boot:run
# либо после mvn package:
java -jar target/video-unique-service-0.1.0-SNAPSHOT.jar
```

API: http://localhost:8080/api/videos/unique

Swagger UI: http://localhost:8080/swagger-ui/index.html

OpenAPI JSON: http://localhost:8080/v3/api-docs

Сервис по умолчанию слушает только 127.0.0.1. Для другого интерфейса задайте `SERVER_ADDRESS`. Аутентификация и публичный хостинг в MVP не входят.

## Запрос

```sh
curl --fail-with-body -X POST http://localhost:8080/api/videos/unique \
  -F 'file=@input.mp4' -F 'speed=1.01' -F 'scale=0.98' \
  -D headers.txt -o unique.mp4
```

PowerShell (используйте именно `curl.exe`):

```powershell
curl.exe --fail-with-body http://localhost:8080/api/videos/unique -F "file=@C:\videos\input.mp4" -F "speed=1.01" -F "scale=0.98" -D headers.txt -o unique.mp4
```

Параметры можно не передавать: `speed=1.01`, `scale=0.98`. Допустимы конечные числа: speed от 0.5 до 2.0, scale от 0.5 до 1.0. Scale уменьшает изображение и добавляет чёрные поля по центру; размеры округляются для H.264 до чётных чисел, поэтому возможна разница в несколько пикселей. Нет обещания, что поля будут скрыты социальной платформой.

Принимаются `.mp4` и, для совместимости с iPhone-примерами, `.mov`. Расширения недостаточно: ffprobe проверяет контейнер семейства MP4/MOV и наличие видео. MIME клиента не считается доказательством формата. Обрабатываются первые видео- и аудиодорожки; субтитры, главы и метаданные не переносятся. Для видео без звука аудиодорожка не создаётся. Скорость звука меняется через atempo с сохранением высоты тона. HDR/цветокоррекция и точное сохранение несquare pixel aspect ratio в MVP не входят.

Ответ: `Content-Type: video/mp4`, `Content-Disposition: attachment; filename=unique.mp4`, `X-Hash-Before` и `X-Hash-After` — полные 64-символьные SHA-256. Ошибки возвращаются как Problem Detail JSON. При ошибке curl может записать JSON вместо видео — проверяйте код возврата и HTTP-статус.

| Статус | Причина |
|---|---|
| 400 | Нет файла, пустой файл, неверное расширение или параметры |
| 413 | Превышен размер загрузки |
| 422 | Повреждённый/неподдерживаемый контейнер или ошибка декодирования |
| 429 | Все слоты обработки заняты |
| 503 | FFmpeg/ffprobe недоступен или запрос прерван |
| 504 | Истёк таймаут процесса |
| 500 | Ошибка файловой системы или другая внутренняя ошибка |

## Настройки и ограничения

`application.yml`: файл до 200 MB, multipart-запрос до 201 MB, два одновременных запроса обработки, два потока кодировщика на FFmpeg. `video.timeout` (по умолчанию 2m, переменная `VIDEO_TIMEOUT`) применяется отдельно к ffprobe и FFmpeg. `VIDEO_MAX_CONCURRENT` меняет число слотов. Загрузка, вычисление хешей и отдача файла не входят в таймаут процесса. Это синхронный API: клиент должен ждать до завершения обработки.

Файлы хранятся на диске во временном каталоге Java; путь можно задать через `-Djava.io.tmpdir=...`. Каждый запрос использует отдельный каталог и фиксированные внутренние имена. После передачи результата, ошибки, таймаута или обнаруженного отключения клиента файлы удаляются в `try-with-resources`. Принудительное завершение JVM/отключение питания может оставить файлы; их можно удалить при остановленном приложении. Требуется свободное место для исходных, промежуточных и выходных файлов; выходной размер отдельно не ограничен.

Процессы запускаются через ProcessBuilder без shell; доступ к протоколам ограничен локальными файлами. Вывод процесса постоянно вычитывается с ограничением удерживаемой памяти. Это не песочница для публичной обработки недоверенных видео: перед публичным размещением нужны изоляция процессов и ограничения ресурсов/доступа. При медленном клиенте слот удерживается до окончания скачивания. Очередь, БД, Docker и Telegram-бот намеренно не включены в MVP.

## Тесты

`mvn test` запускает тесты параметров, SHA-256, очистки, ограничения параллелизма, обработки ошибок процесса, контроллера, OpenAPI и Swagger. Тесты JUnit 5.14.1; его версия явно зафиксирована вместо управляемого Boot JUnit 6. Spring Framework 7 SpringExtension требует JUnit 6, поэтому API-тесты сами запускают и закрывают Spring-контекст, без SpringExtension. Интеграционные тесты FFmpeg по умолчанию пропускаются явно (два теста); для реального кодирования:

```sh
RUN_FFMPEG_TESTS=true mvn clean verify
```

```powershell
$env:RUN_FFMPEG_TESTS='true'
mvn clean verify
```

Они генерируют двухсекундные видео с аудио и без него и проверяют кодеки, длительность, разные хеши и отказ на повреждённом файле. FFmpeg и ffprobe должны быть доступны через PATH или указанные переменные окружения. Пользовательские видео и результаты не включаются в Git.

## Архитектура

- `controller`: multipart и HTTP, потоковая передача с диска без загрузки всего результата в память.
- `service`: ограничения параллелизма, временные файлы, хеши, ffprobe/FFmpeg и управление процессами.
- `config`: типизированные настройки.
- `dto`: неизменяемые параметры обработки с проверкой инвариантов.
- `exception`: единый контракт ошибок без раскрытия stderr и локальных путей.

Spring dependency injection; без Lombok, preview-функций Java и внешних сервисов.
